# Component contract

All components are implemented in `src/components`; `Graphic.tsx` is the exhaustive dispatcher. `schemas/graphics-plan.ts` is the authoritative typed props contract. No component accepts CSS, a font name, a color, a duration in seconds, or arbitrary JavaScript from a plan. Each cue reserves a normalized `{x,y,w,h}` box; choose its anchor and box together. The anchor selects vertical alignment, while the explicit box is authoritative for placement and QA.

Default motion: Clean Tech uses 12 entry / 8 exit frames at 30 fps; Cinematic Doc 15 / 9; High-Energy Shorts 9 / 6. Multiply by source fps / 30 and round, preserving the source rational frame rate. Hold duration is at least `max(1.5, words / 3 + 1)` seconds **after** entry and **before** exit. Lists add the last item's stagger to that minimum. Captions follow actual word intervals; transitions have no reading hold. Typography uses the shorter frame dimension as its unit (1080 for both 1080p landscape and portrait), so portrait text does not become oversized merely because the frame is tall.

Styling follows print editorial rather than UI cards: large display type, small tracked mono labels (kickers, attributions, indices), hairline rules and one accent. The preset `surface` decides legibility. `solid` (Clean Tech) sets text on flat, square ink strips that hug their content, so token contrast is guaranteed. `bare` (Cinematic Doc, High-Energy Shorts) sets type directly on footage with a soft glyph shadow and no box; contrast depends on the shot, so QA warns and the reviewer must check each cue frame. Code and callout labels always use solid ink. There are no rounded corners, drop-shadowed cards or glows. Text is clipped to the approved cue box, and render QA measures actual loaded-font text bounds during the hold to reject overflow instead of silently shrinking type. During entry/exit, visual QA checks intentional clipping and changing opacity. Baked Lottie text must be converted to outlines. Uploaded images and Lottie artwork require visual contrast and content review.

## Adding a component

Write a spec describing its editorial job, anatomy, typed props, both aspect ratios, timing and failure modes. Add any new styling to tokens and review it across all presets. Extend the discriminated union and exhaustive dispatcher. Add deterministic fixtures, safe-area/reading-time behavior tests and both-aspect visual baselines. Inspect the snapshots, run all checks, document asset licensing, then update CHANGELOG. Per-video requests compose existing components; a new component is a separate engine contribution.
