# Motion graphics finishing

Use the installed engine. Compose the existing vocabulary through `projects/<slug>/graphics-plan.json`. Read [README.md](README.md) for commands, [docs/editorial-rubric.md](docs/editorial-rubric.md) for selection/timing, and [docs/components.md](docs/components.md) for props and component limits. Use `schemas/graphics-plan.ts` as the source of truth. For typography selection read [docs/typography.md](docs/typography.md); choose a registered `fontPairing`, disclose its substitutions, and never download an ambiguous or proprietary face without confirming its rights.

1. **Check inputs and capabilities.** Obtain the locked media path, platform, any verified identity/brand facts, and audio preference from the user's brief. Default to source aspect, Clean Tech, selected key phrases and `audio.mode=preserve`. Run `npm run mg -- doctor`. Install documented dependencies if authorized by the task/environment; otherwise name the missing dependency and the specific fallback. Never claim an analysis stage ran if it did not. Never retime, recut, reorder or modify the source.
2. **Ingest.** Run `npm run mg -- init '/absolute/path/locked.mov' --slug <slug>`. Check resolution, frame count, rational fps, duration, color, rotation and audio. Stop on source-contract warnings (VFR, HDR, interlace, non-square pixels, rotation, nonzero video origin). Explain that a separately approved finishing master is needed; do not silently conform the locked edit. Use a new slug if the source bytes change.
3. **Analyze.** Run `npm run mg -- analyze --project <slug>`; use `--transcript <json>` for an available word-timestamped transcript and `--model` / `--language` as needed. Analysis is local; the first ASR invocation downloads its selected model. Do not upload footage or transcript to an LLM service implicitly. Review `analysis/transcript.json` against speech; it is canonical for words. Correct spelling, names, numeric precision and word timings. Keep all timing in integer source frames and half-open intervals.
4. **Review shot safety.** Inspect each shot's first/middle/last images and A-roll samples, then watch moving subjects between samples. Read `analysis/analysis.json`; sampled face/motion boxes are conservative proposals, not a complete tracker. Add or correct human-provided `face`, `subject`, `ui` and `text` regions, each with its true frame interval and normalized box. Mark a shot `reviewed: true` only after reviewing it. Clear `analysis.needsInput` only after resolving the issue. Unknown facts go in the plan's `needsInput` list as `[NEEDS INPUT] ...`; omit unsupported graphics.
5. **Draft and edit the plan.** Run `npm run mg -- plan --project <slug> --preset clean-tech --platform youtube` (or supported alternatives). The command preserves an existing human-edited plan. Read `analysis/semantic-candidates.json` and the editorial rubric; it is a rule-based shortlist, not a final story analysis. Identify hook, sections, stats, lists, comparisons, tools, quotes, identities, punchlines and CTA from actual evidence. An optional agent semantic pass may edit the local plan directly. Select existing components, exact text, approved assets, source references, boxes, layers, priorities and sync frames. Keep transcript references verbatim contiguous excerpts; cite brief facts explicitly. Never invent names, titles, measurements or quotes. Never add a graphic just to satisfy a component checklist.
6. **Self-review and preview.** Check reading holds, density, safe areas, faces/UI, contrast, word/cut boundaries, emphasis landings and end-screen slots. Choose no cue when no safe space exists. For a moving target, split static annotations and review their boxes; this engine does not claim automatic object tracking. All source-level camera moves and transitions that alter the edit are prohibited; the still-motion component only animates a separate licensed inset. Run `npm run mg -- preview --project <slug>` and `npm run mg -- qa --project <slug> --frames`. Fix errors in JSON and inspect generated cue-edge/midpoint frames. For complex motion, scrub intervening frames and watch the sequence. Keep final audio preservation unless the user specifically chooses normalization or SFX. SFX live on separate dry/ducked stems and are listed in the plan.
7. **Stop for the human graphics-plan approval gate.** Present the concrete plan, cue reasons, unresolved inputs (ideally none), representative style/cue frames, audio mode and preflight report. Ask the human to approve that exact result. The repository's explicit workflow requires this review; do not execute `approve` yourself without the user's explicit approval of the presented result. The user can record approval with `npm run mg -- approve --project <slug> --reviewer 'Name'`. A general instruction to finish a video does not bypass this repository's requested plan gate. A prior explicit approval of this exact result does. Never synthesize an approval record or reuse an approval after the plan, analysis, assets or engine changed.
8. **Render the approved plan.** After approval, run `npm run mg -- render --project <slug>`. A stale approval is an error, not a reason to edit the approval hash. The renderer emits `renders/composite.mov` (H.264 High, original audio copy by default) and `renders/overlay.mov` (ProRes 4444 with alpha). Audio remix modes emit separate PCM/SFX artifacts. Caches are content-addressed; rerun a failed command after fixing its actual cause. Do not delete an active lock; remove a stale `.cache/lock` only after confirming no process owns the project.
9. **Finish QA.** Run `npm run mg -- qa --project <slug> --frames --final`. Inspect the final output, not only the Studio preview. Watch through with audio, including every cut and cue edge; inspect opacity, actual background contrast, descenders, alpha in the target NLE, factual spelling, sync and read time. Review machine checks for frame count/fps, audio hashes/timing, clipping, alpha format and artifact integrity. Do not call a manual review complete if only automated checks ran. Fix failures and obtain renewed approval if the plan/engine changed, then rerender and repeat affected QA.
10. **Deliver.** Link composite, alpha overlay, optional audio stems, plan/cue sheet, preset/style spec, QA findings and fixes, asset licenses and any remaining `[NEEDS INPUT]` items. State validation limits honestly. Keep source media, rendered video and caches out of git. Commit-worthy changes are engine code, project plan/analysis JSON where appropriate, documentation and reviewed test snapshots.

## Engine contribution boundary

Never regenerate, restyle or fork components inside a per-video project. Prefer shortening text, splitting cues or choosing another existing component. If the vocabulary truly cannot serve the verified editorial need, propose a separate engine contribution: **component spec → token-only styling → typed schema/registry extension → deterministic and visual tests in both aspects and all presets → documented licenses → CHANGELOG**. Follow [docs/components.md](docs/components.md). Do not introduce requestAnimationFrame, CSS animation/transition, Date-based rendering, internal animation tickers, unseeded randomness, asynchronous animation state or network assets. GSAP builders must be memoized, paused, explicitly initialized with `fromTo`, and driven only by `useGsapTimeline`.
